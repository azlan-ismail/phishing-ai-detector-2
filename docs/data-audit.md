Features are coarse numerical encodings in the range -1 to 1. Repeated feature vectors are not proof of duplicate URLs, and conflicting labels do not necessarily establish labeling errors. Do not automatically delete or relabel these observations.

The row count, feature count, and displayed feature names resemble the [UCI Phishing Websites dataset](https://archive.ics.uci.edu/dataset/327/phishing), which lists 11,055 instances and 30 features. This is a provenance lead, not a verified identity or source-label mapping. The existing notebook calls Result=1 phishing; that assertion still requires source evidence. No remapping was performed.

## Existing evaluation findings

Reconstructing the current training script's single 70/30 permutation (random_state=42, no stratification) gives 7,738 training and 3,317 test rows. Test-label counts are 1,428 raw -1 and 1,889 raw 1, matching the supports in the saved metric files.

- 2,038 test rows have an identical full row in training.
- 2,053 test rows have an identical feature vector in training, regardless of label.
- This warrants a feature-group sensitivity evaluation and provenance investigation. It does not prove URL-level leakage or quantify performance inflation.
- Saved class-1 precision, recall, F1, support, and overall accuracy agree arithmetically with the stored confusion matrices for LR, RF, and XGBoost. This does not validate the source labels or reproduce model training.
- The threshold notebook evaluates and selects thresholds on the entire dataset. Its selected values are not independent validation-selected thresholds.
- The adversarial script samples from the full dataset, allowing training examples into evaluation. It also declares clip_values=(0,1), whereas source features include -1. Attack-domain constraints need review before these results are reused.

## Reproduce the audit

Run from the repository root:

```bash
python scripts/audit_dataset.py data/phishing.csv --label-column Result --output research/audits/phishing.audit.json
python scripts/audit_legacy_results.py > research/audits/legacy-results.audit.json
python -m unittest discover -s tests -v
```

The dataset script uses only the Python standard library. The legacy-results script additionally uses NumPy, already listed in requirements.txt. Reports contain aggregate values, not raw URLs. Neither script loads saved model objects, trains models, changes data, or infers class meanings. Duplicate checks compare exact recorded strings. The legacy split reconstruction assumes the current row order and the settings in the existing script; it does not inspect fitted-model provenance.

Machine-readable evidence: [dataset audit](../research/audits/phishing.audit.json) and [legacy-results audit](../research/audits/legacy-results.audit.json).
